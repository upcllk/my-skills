# 本地 MySQL MCP 配置

维护 `~/.mcp/mysql-servers.json` 中的服务器定义，并将它视为唯一可编辑的事实来源。该文件包含凭据，绝不得提交、复制到本技能、在对话中引用或打印到命令输出。

## 维护源配置

1. 检查 `~/.mcp/mysql-servers.json` 时不得显示凭据。文件存在时，先解析；JSON 格式错误则停止并报告，不得引用源内容。
2. 仅准备用户请求的新增、变更或移除。仅在文件不存在时创建，并使用顶层 `mcpServers` 对象。每项必须包含字符串 `command`、字符串数组 `args` 和值均为字符串的 `env` 对象。保留无关条目和字段。
3. 面向只读数据库服务时，三个标志 `ALLOW_INSERT_OPERATION`、`ALLOW_UPDATE_OPERATION` 和 `ALLOW_DELETE_OPERATION` 都设为 `"false"`。未经明确授权不得放宽已有限制；这些标志不能取代数据库侧权限。
4. 写入前展示精确文件路径、受影响服务器名和不含凭据的拟议操作，并取得确认。仅在明确授权时移除条目。
5. 写入已批准的源文件变更，保持文件权限为 `600`，并确认最终 JSON 和条目结构有效。此流程不得修改客户端配置或连接数据库。

## 客户端兼容性

`~/.mcp/mysql-servers.json` 是本环境的共享源约定，不保证每个客户端都会自动发现它。支持此路径的客户端可按各自文档的加载方式使用。

不得声称 Codex 原生读取此文件。此前集成会将它转换为 `~/.codex/config.toml`；未另行建立适配器时，编辑 JSON 不会更新 Codex 的 MCP 配置。客户端集成需要单独请求，不属于默认流程。

保留的 `scripts/sync-mysql-mcp.mjs` 属于旧版多客户端同步流程。源文件维护期间不得调用它，包括其试运行模式。

不得自动检查或编辑其他客户端文件、运行客户端启用命令，或要求重启客户端。

## 安全要求

- 凭据只能保留在本地文件中；所有日志和回复中均应隐藏密码、令牌和连接串。
- 默认不得创建具备生产写权限的配置。
- 仅请求变更个别条目时，绝不得整体替换既有源配置。
- 不得从源文件维护请求推断出同步客户端、连接数据库或修改数据库权限的授权。

## 交接

报告源文件路径和受影响服务器名及其操作，不得包含配置值。明确区分源文件更新和客户端启用：不得仅因 JSON 已更新就声称 Codex 或其他客户端已应用该变更。
